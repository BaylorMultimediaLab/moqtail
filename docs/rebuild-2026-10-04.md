## Event contract changes

All events keep their existing fields unless stated. New fields are
additive so old bundles still parse.

### Switch identity (fixes C1)

- `SWITCH_SENT` gains `switch_seq` (per client session, starts at 1,
  monotonic). Every later record of the same switch carries the same
  `switch_seq`: `SWITCH_FLOOR` (pr1378), `SWITCH_OK`, `SWITCH_ERROR`,
  `SWITCH_SKIPPED`, `SWITCH_FIRST_OBJECT`, `SWITCH_APPLIED`,
  `SWITCH_FIRST_FRAME`, `SWITCH_SUPERSEDED`.
- `SWITCH_SUPERSEDED {switch_seq, by_switch_seq, playhead_ms}` is emitted
  when a newer switch lands before this one's seam was presented (the
  pending seam is overwritten). A switch therefore ends in exactly one of:
  `SWITCH_FIRST_FRAME`, `SWITCH_SUPERSEDED`, `SWITCH_ERROR`,
  `SWITCH_SKIPPED`, or none (run ended first).
- The analyzer joins by `switch_seq` when present. For bundles without it
  the fallback join is: the last `SWITCH_SENT` with `ts <= ff.ts` whose
  `from` and `to` both match; every other unresolved switch to that target
  is superseded.

### Landing and seam (fixes M9, M10)

- `SWITCH_FIRST_OBJECT`: unchanged, the landing object (`group`, `object`,
  `landed_on_keyframe` moves here as well).
- `SWITCH_APPLIED` is emitted when the first target object passes the
  keyframe gate, i.e. the first object actually appended. Its
  `new_start_pts_ms`, `media_seam_gap_ms`, `seam_ahead_of_playhead_ms`
  refer to that object. New fields: `landing_object` (index of the landing
  object), `first_appended_object`, `discarded_before_keyframe` (objects
  dropped between them), `landed_on_keyframe` (of the landing object,
  kept for continuity).
- `SWITCH_FIRST_FRAME` fires only for a presented frame whose `mediaTime`
  lies in `[seam_pts, target_append_front]` at the time of presentation,
  where `target_append_front` is the end PTS of the last appended target
  object. New fields: `seam_behind_playhead` (bool,
  `seam_ahead_of_playhead_ms < 0` at landing), `source: 'rvfc' | 'raf'`.

### Samples and throughput (fixes M11, M12, M13)

- `SAMPLE` gains `buffer_contig_s` (end of the buffered range containing
  the playhead minus playhead; 0 if none) and `presented_track` (the track
  whose frames are being presented, resolved from the playhead against the
  list of (seam_pts, track) transitions). `buffer_s` keeps its meaning
  (last range end minus playhead) and is renamed in the docs as the total.
- `STALL_START.track` is the presented track.
- The library stamps `recvAt` (`performance.now()`) on every object at
  enqueue in the data-stream handler. `THROUGHPUT_SAMPLE` is computed from
  `recvAt` of the first and last object of the group (arrival spacing),
  gains `discarded_bytes` (bytes of objects of that group dropped by the
  player or the library) and `track` is the track the group belonged to.
- `DROP_STALE` gains reason `unrouted` (library-level discard of a stream
  whose alias has no route; `bytes` counted from the stream) and the
  library cancels such a stream with STOP_SENDING.

### Seeks and gaps (fixes M14)

- One gap-crossing policy. `SEEK.reason` is one of `startup`, `gap`
  (the playhead crossed a buffered hole or jumped to a later range; fields
  `from_ms`, `to_ms`, `gap_ms`, `deferred_ms`), `wedge` (no later range
  existed; recovery seek). The analyzer accepts the old reasons
  (`range-jump`, `unwedge`) as `gap`.
- `media_skipped_ms` per run = sum of `to_ms - from_ms` over `gap` seeks
  after the initial window.

### Relay and runner events

- `RELAY_CONFIG` (relay, at start): every resolved config field, including
  `congestion_controller`, `t_switch_ms`, alias timeouts, keep-alive, idle
  timeout, cache size, `forward_promotion_trigger`,
  `native_status_before_subscribe` (R3-D4: relay flag
  `--native-status-before-subscribe`, default false = upstream order, SWITCH
  statuses set after the SUBSCRIBE succeeded; true = set before it).
- Native arms (R3-D7): as shipped = neither `--forward-promotion-trigger` nor
  `--native-status-before-subscribe`; fixed (`--mechanism native
--mechanism-mode forward-trigger`, rebuild/native-ft) = both. The runner
  requires both flags in `relay --help` for the fixed arm and refuses a run
  whose RELAY_CONFIG does not report both fields true (fixed) or both false
  (every other run).
- `PUBLISHER_CONFIG` (publisher, at start): ladder with bitrates, GOP,
  priority per variant, cache path and `meta.json` hash.
- `SWITCH_PROMOTED` (native) gains `old_track`, `old_last_sent_group`,
  `trigger_forwarded`. New `SWITCH_DEMOTED {old_track, last_group}`.
- `SWITCH_WAIT` (pr1378): emitted when selection waits for the floor to
  materialise; `floor`, `live_edge_current`, `live_edge_target`.
- `NET_CHANGE` gains `tc` (resolved command lines), `qdisc_stats` (`tc -s`
  output for the bottleneck leaf: bytes, packets, drops, backlog) and
  `offloads` (`ethtool -k` summary). `RUN_END` carries the final
  `qdisc_stats`.
- `OBJECT_SENT.sent` is true only when the QUIC write succeeded.
- `CONN_STATS` unchanged.

### Identity

`run_meta.json` / `identity` gain `congestion_controller`, `relay_config`
(the RELAY_CONFIG record), `cache_meta_hash`, `kernel`, `tc_version`,
`offloads_disabled`, `warmup_s`, and drop `seed`. `controller` values:
`baseline`, `grid`, `min`.

## Controller `min` (W5)

Mechanism-neutral and client-type-neutral by construction. Inputs:
throughput SWMA over the last 5 group samples (arrival-spaced), the
contiguous buffer envelope, the instantaneous contiguous buffer, and the
switch history.

- `ThroughputRule`: up when `0.9 × SWMA ≥ bitrate(i+1)` and the dwell is
  satisfied; down to the highest rung with `bitrate ≤ 0.9 × SWMA`.
  Dwell: no up-switch until `upDwellGroups` (default 3) complete groups
  of the current rung have been received since the last landing.
- `EmergencyBufferRule` (STRONG): contiguous buffer `== 0` → rung 0;
  `< 0.5 s` → highest rung with `bitrate ≤ 0.7 × SWMA`. Instantaneous
  value, not the envelope.
- `SwitchHistoryRule` in veto mode, 60 s window, counting only drops that
  happen more than `historyIgnoreGroupsAfterLanding` (default 2) groups
  after a landing.
- Buffer signal: envelope of `buffer_contig_s` (1250 ms).
- Everything else off: BOLA, Probe (and the probe track), InsufficientBuffer,
  BufferDrainRate, LatencyTrend, Abandon, L2A, LoLP, DroppedFrames.
- History and `ABR_DECISION` are recorded in `onTrackSwitched` only when
  the landed track equals the target (no phantom switches), for all arms.
- The probe denominator bug is fixed for `grid` regardless.
- `RUN_META.controller` records the arm and every effective constant
  (tick, dwell, window, envelope, safety factors).

Runner: `--controller min` is the default for every batch from now on;
`grid` and `baseline` remain selectable.

## Transport fairness (W3, W4)

- Every SUBSCRIBE and every SWITCH from the player carries
  `SubscriberPriority(0)` and `GroupOrder(Ascending)` on every branch; the
  relay's promoted/target subscription uses them (native keeps the original
  subscription's priority; pr1378 reads them from the SWITCH parameters).
- Publisher: one priority for all video variants (flag
  `--variant-priority`, default 128, recorded in PUBLISHER_CONFIG).
- Probe stream priority derived from `compute_stream_priority(255, 255,
Ascending, u64::MAX)` so it is below every video stream for any
  subscriber priority.
- Control and request streams (R3-D2, harness, every arm): the relay's control
  stream, every bidi request stream it accepts, the PUBLISH streams it opens
  toward subscribers and the SUBSCRIBE/TRACK_STATUS/FETCH streams it opens
  upstream run at `CONTROL_STREAM_PRIORITY` = i32::MAX. Data priorities are
  shifted one below it (saturating at i32::MIN), so control > every video
  band > probe. FETCH response streams use `compute_stream_priority` with the
  FETCH's SubscriberPriority (128 if absent), GroupOrder, the default publisher
  priority and the first group (was a literal 0).
- Every stream is opened with its priority in place before the first byte
  (R3-D6): on WebTransport the QUIC stream is opened directly, prioritised, and
  the WebTransport header written after (quinn queues a stream at the priority
  it has at its first write).
- Data streams (R3-D3, R3-D5): a stream the subscriber stopped is not reopened;
  the rest of that subgroup is dropped. A joining replay finishes the streams of
  groups whose publisher stream has closed (the newest group continues live).
- Relay `--congestion-controller cubic|bbr`, default `cubic`; runner passes
  it explicitly and records it; a `--cc bbr` runner flag exists for the
  sensitivity batch.
- Relay keep-alive and idle timeout, alias timeouts and T_switch are passed
  explicitly by the runner with identical values on every branch.

## Shaping (W2)

One topology for both queue models, host-side egress (relay → client):

```
root netem delay 20ms limit 10000          # propagation, never the bottleneck
  └ htb rate R ceil R                      # the bottleneck rate
      └ leaf: bfifo limit <queue_bytes>    # tail-drop, bytes (queue_pkts × 1500)
          or fq_codel limit 10240 target <t> interval 100ms
```

Client-side egress: `netem delay 20ms limit 10000` (no rate). Offloads
(`gso`, `tso`, `gro`, `tx-udp-segmentation`, `rx-udp-gro-forwarding`)
disabled on both veth ends in both namespaces before any qdisc is added;
`ethtool -k` recorded. Amended 2026-10-04: device offloads do not stop
QUIC's own UDP segmentation (quinn sends with `UDP_SEGMENT`; the kernel
keeps each batch as one skb through the qdisc and segments it after
dequeue). The relay therefore runs with `--udp-gso off` (quinn
`enable_segmentation_offload(false)`), recorded as `RELAY_CONFIG.udp_gso`,
and the runner reports `gso_at_qdisc` from the leaf's `maxpacket`. Capacity steps use `tc class change` (and
`tc qdisc change` for the leaf) so nothing queued is dropped. codel
`target` = max(5 ms, 1.5 × MTU time at the step's rate), recorded. The
resolved commands and `tc -s qdisc` are recorded on every NET_CHANGE.
Whether netem accepts a child qdisc on the target kernel is checked by the
preflight (`tc qdisc show` after setup must list all three levels).

Runner: fixed warm-up of 15 s for both client types, gated on the first
publisher GROUP_EMIT; readiness checks for relay (listening line) and
client (STARTUP within 30 s); refuse `duration + warmup + 30 > gops`;
aborted runs write an invalid `validation.json`; `--seed` removed;
`run_grid` in the guide becomes repetition-major (every arm once per rep).

## Preflight (W1 validator + guide)

`validate.py --preflight` on a 60 s run asserts, per arm and client type:

- keyframe landings = 100 % (every arm except as-shipped native, where the
  fraction is reported, not asserted);
- `landed_behind_playhead` = 0;
- every switch ends in exactly one terminal record;
- `DROP_STALE{unrouted}` bytes = 0 after the first switch has settled
  (reported if not);
- `RELAY_CONFIG.congestion_controller` matches the run identity;
- `qdisc_stats` present on every NET_CHANGE and the tc tree has the
  expected three levels;
- on the unshaped profile: CONN_STATS loss rate < 0.1 %;
- `gso_at_qdisc` false on every NET_CHANGE of a rate-limited profile, and
  the leaf's `maxpacket` ≤ 1514 B (fail above 3000 B, report between);
  `RELAY_CONFIG.udp_gso` = `off`;
- delivery rate (amended 2026-10-04; replaces the probe check, since `min`
  runs without the probe): for each rate-limited step, over
  `[step + 10 s, next step)`, the median `THROUGHPUT_SAMPLE` rate of
  link-limited groups (bytes × 8 / 50 ms ≥ rate) lies in `[0.6, 1.15] × rate`.
  Out-of-band steps are attributed with the probe's pure transfer rate in
  the same window (probe as low as video = transport; probe near the rate =
  client-side timing). In fresh-grid-v2, 14 of 30 runs fail after the
  restore to 6 Mbps with video and probe both at 1.2-1.7 Mbps on all arms
  and both client types: the relay's connection kept delivering the low
  step's rate (BBR then; CONN_STATS now records cwnd and rtt to show why).
  This is a transport effect, not the estimator; it must not recur under
  CUBIC before any batch counts.

The guide section 12 gives the Linux commands: preflight for each arm and
client type, repeated three times, then the grid.
