# Apparatus audit, 2026-10-04

Read-only review of every component the experiments depend on, done after the
grid kept surfacing one defect per batch. Eight reviewers, one per component,
each with a fixed charter; their full reports are in
`audit-2026-10-04-reports.md`. This file is the synthesis: what is wrong, why
each item matters for the comparison, and the order in which to fix it.

Scope: the `harness` branch (player, ABR controller, client library, relay,
publisher, runner, shaping, analyzer, validator, plotting) and the three
mechanism branches (`switch/native` with `--forward-promotion-trigger`,
`switch/pr1378`, `switch/pr1674`). Nothing was changed by the audit.

## 1. Verdict

The experiment design is sound: one shared player, controller and analyzer;
mechanism code only on the mechanism branches; two client types expressed
only through the SUBSCRIBE parameters. The runner is also sound (fresh netns
and profile per run, branch guard, identical flags per arm, per-run
validation).

The reason every batch produced a new defect is that four layers each carry
problems that only show up as data, and the data was being read before those
layers were verified:

1. **Measurement.** The analyzer joins the first-frame record to the wrong
   switch whenever a target repeats; "played rung" is the subscribed rung;
   censored values are dropped; media skipped by watchdog seeks is not a QoE
   number. Two of the headline rows (visibility delay, superseded count) are
   wrong by 2x to 10x on the current tables.
2. **Controller.** Two rules in the frozen `grid` arm behave differently per
   client type by construction, a one-group seam hole is turned into a 60 s
   ladder cap, and there is no dwell time, so part of what the tables show as
   "mechanism" is the controller reacting to its own inputs.
3. **Transport and priority.** The pr1378 client sends SWITCH without
   parameters, so its subscriber priority drops from 0 to 128 at the first
   switch and from then on the probe, control streams and the old
   subscription's leftover bytes outrank all new video. The publisher gives
   every variant a different priority, so which track is served first at a
   seam depends on ladder order. The shaper's "100-packet" queue counts
   GSO super-packets, every capacity step deletes and recreates the qdisc,
   and BBR's initial window is twice the queue. The post-switch pauses of
   section 11e are these, not the mechanism.
4. **Mechanism conformance.** The pr1674 relay never completes a SWITCH_FROM
   for stream media (the activation call site is commented out upstream), so
   that arm cannot be admitted yet. The pr1378 client stops reading the old
   subscription at SWITCH_OK, so the relay's below-seam drain is sent and
   never consumed. The forward-trigger flag can forward a mid-group object on
   one path. As-shipped native is what it is (a measured upstream defect).

None of this invalidates the design. It means the apparatus has to be made
correct layer by layer and then re-verified with a preflight before any run
is read as a result. The guide's instinct ("if the apparatus is right, the
data takes care of itself") is the right one; the audit is the list of what
"right" requires.

### Minor (see the reports)

Rate controller cannot settle on 1 s group bursts (live-edge stalls partly
measure player tuning); init-apply failure path skips the keyframe gate;
append front updated before the append succeeds; throughput sample attributed
to the current track; rAF fallback not flagged; RUN_META before override
merge; warm-up differs per client type (8 s content offset at the step);
cache length margin thin; no readiness checks; `--seed` unused; arm-major
run order; event-log flush in the forwarding hot path; one PRFT per GOP;
schema drift (SEEK reasons, `SWITCH_SKIPPED`, `request_id: null` on pr1674);
`auto-emergency` dead; slow-start instant on time-shifted clients; tie-break
by insertion order; many unused settings and dead code paths.

## 3. What is verified correct

Worth stating so the rebuild does not touch it: client types are pure
SUBSCRIBE parameters with no mechanism branch; the switch timestamps are
taken at the right moments; the keyframe gate drops before any bookkeeping;
`landed_on_keyframe` reads the real sync flag; stall episodes do not double
count within the player; live-edge distance is PRFT-based and identical for
all arms; controller code is byte-identical on the three branches; the
runner's identity block, branch guard, per-run netns and profile, and
validation flow; publisher pacing is anchored and all variants emit a group
at the same instant with the keyframe at object 0; the pr1378 G_switch
selection is exact (oracle-tested) and its catch-up/live partition is
duplicate-free; cache cannot evict within a run.

## 4. Rebuild order

No batch is read as a result until step 6 passes. Steps 1-5 are independent
of each other and can be done in parallel; each lands as its own commit with
a test that reproduces the finding first.

1. **Measurement (analyzer + validator).** Fix the first-frame join (C1);
   presented-rung series from first-frame transitions weighted by advancing
   playhead time (M13); `media_skipped_s`; stall episodes ≥ 250 ms with blips
   reported separately; censored metrics as "fraction with event + median
   with never = ∞" (M19); reaction rows only from the `detect_step`
   experiment with the "rung at t0 above fit" precondition (C2); validator
   requires RUN_END, sample count ≈ duration/0.25, all NET_CHANGE applied,
   and `relay_promoted_ms` where the mechanism has it; aborted runs written
   as invalid (M20). Re-analyze fresh-grid-v2 and publish the corrected
   table so the size of C1 is on record.
2. **Player and library.** Seam fields from the first appended target object
   (M9); first-frame only when a target frame is presented, with
   `seam_behind_playhead` logged (M10); receive timestamp at enqueue and
   throughput from it (M11); `buffer_contig_s` for the ABR (M12);
   `presented_track` in SAMPLE (M13); one gap-crossing policy (M14);
   unrouted-stream event with STOP_SENDING (M15); request-error, alias
   release guard, pushed PUBLISH_DONE (M16).
3. **Transport fairness (all arms, identical).** SWITCH and SUBSCRIBE carry
   subscriber priority 0 on every branch (C3); uniform publisher priority
   across variants (M3); probe priority derived relative to video; record
   the congestion controller in RUN_META and decide BBR vs CUBIC once (M4);
   keep CONN_STATS.
4. **Shaping.** Disable GSO/TSO/GRO on both veths and record `tc -s qdisc`
   and `ethtool -k` at each step (C5); change rate in place instead of
   del/add (M1); one topology for both queue models so tail-drop vs
   fq_codel differ only in the leaf, with codel target ≥ 1.5 × packet time
   at the lowest rate (M2); pin every relay timeout from the runner and emit
   a RELAY_CONFIG event (M20); fixed warm-up for both client types;
   interleave arms per repetition.
5. **Mechanisms.** pr1378: keep reading the old subscription until its
   PUBLISH_DONE, drop old-track objects ≥ G_switch once SWITCH_OK carries
   it, catch-up priority within the subscriber band, attach-before-terminate,
   PUBLISH_DONE handler, `lastGroupId` as max, SWITCH_WAIT event (M5, M6).
   native-ft: require `object == 0` for the forwarded trigger and exclude the
   trigger's group from the replay (M7). pr1674: restore `complete_switch`
   on first delivery, hard mode via NextGroupStart, label soft as playhead
   refill, add the relay unit tests, then run the 10b gate (C4, M8).
   As-shipped native: unchanged, it is the upstream baseline.
6. **Controller.** Replace `grid` with a minimal mechanism-neutral arm
   (`min`): ThroughputRule on the group SWMA with an up-switch dwell of N
   completed groups; one emergency rule (instantaneous contiguous buffer
   empty or < 0.5 s); history veto that ignores drops within two groups of a
   landing; envelope buffer signal; latency-trend, probe, BOLA, drain-rate
   and the buffer-scaled admission off; history recorded only on confirmed
   switches (C6, M17, M18). Keep `grid` runnable for the ablation record.
7. **Preflight.** One 60 s run per arm × client type, unshaped and at
   1.5 Mbps, with hard invariants checked by the validator before any batch:
   keyframe landings 100 % on every arm except as-shipped native; behind-
   playhead landings 0; every switch has either its own first frame or a
   superseded flag; unrouted bytes 0; CONN_STATS loss rate below a threshold
   on the unshaped link; RUN_END present; queue depth recorded.

Then the grid once, with the three arms (as-shipped native, native-ft,
pr1378) and, if its gate passes, pr1674 in both modes.

## 5. Metric set for the paper

Headline (one table, per client type × mechanism, median over reps with all
points shown):
